# AGENTS.md — Правила разработки для AI-агентов (PeerCheck)

Этот файл задаёт контекст, ограничения и архитектурные правила для AI-ассистентов (Copilot, ChatGPT, Cursor, Claude и др.), которые работают с кодом проекта **PeerCheck**.

---

## 1. Контекст проекта и команды

* **Продукт:** веб-сервис анонимного взаимного рецензирования студенческих лабораторных работ (P2P-ревью).
* **Команда:** студенты 1-го курса под руководством наставника.
* **Специфика:** студенты только осваивают Python и Git. Они должны **понимать каждую строчку кода**, уметь объяснить его на созвоне и защитить перед преподавателем. Если студент просит написать код, объясни, что делает каждая часть. Не добавляй ничего сверх того, что требует задача.
* **Главный принцип:** **KISS (Keep It Simple, Stupid)**. Простота и читаемость важнее «продвинутых» абстракций.

---

## 2. Технологический стек и ограничения

| Компонент | Разрешено | Запрещено |
| :--- | :--- | :--- |
| **Язык** | Python 3.10+, синхронный код | `async/await`, `asyncio`, метаклассы, сложные замыкания |
| **Интерфейс** | `streamlit` (стандартные виджеты) | Внешние JS-фреймворки, сложный самописный CSS/HTML (кроме iframe для PDF) |
| **База данных** | Встроенный модуль `sqlite3`, файл `peercheck.db` | ORM (`SQLAlchemy`, `Peewee` и др.), сложные SQL-процедуры |
| **Файлы** | `pathlib.Path`, `os`, `shutil`, каталог `uploads/` | Облачные хранилища (S3, MinIO) |
| **Зависимости** | Только то, что в `requirements.txt` (`streamlit`) | Новые пакеты без согласования с наставником |

## 3. Архитектура

Код разделён на **3 модуля в корне**, у каждого свой ответственный:

```text
peer-check/
├── app.py                # [Виталина] Интерфейс Streamlit
├── database.py           # [Кирилл] Работа с SQLite (CRUD-функции)
├── roulette.py           # [Егор] Логика рулетки и валидации
├── test_roulette.py      # Автотесты для roulette.py
├── seed_demo_data.py     # Тестовые данные для «холодного старта»
├── requirements.txt
├── AGENTS.md             # Этот файл
├── peercheck.db          # Локальная БД (в .gitignore, не коммитится)
├── uploads/              # Загруженные PDF (в .gitignore, не коммитится)
└── docs/                 # Документация для команды
    └── architecture_contracts.md  # Схема БД и сигнатуры функций
```

### Правило контрактов
* **Не придумывай новые имена функций!** Все вызовы между `app.py`, `database.py` и `roulette.py` зафиксированы в [docs/architecture_contracts.md](docs/architecture_contracts.md).
* Если нужна новая функция, сначала договорись с наставником и добавь её контракт в этот файл.
* Сигнатуры в `roulette.py` дополнительно проверяет `test_roulette.py`. Не меняй их.

### Git
* Пока работаем напрямую в ветке `main` (Commit ➔ Push), без фиче-веток.
* Коммить только файлы своей задачи. Не коммить `.venv/`, `.idea/`, `*.db`, `uploads/`.

## 4. Стиль кода

1. **Docstring и комментарии:**
   * У каждой публичной функции краткий docstring на русском: что делает, какие аргументы, что возвращает.
   * Неочевидные шаги внутри функции комментируй простыми словами.
2. **Аннотации типов** пиши встроенными типами (Python 3.10+), без `typing.List/Optional`:
   `def add_submission(student_token: str, lab_number: int, file_path: str) -> int:`
   `def select_lab_for_review(current_user_token: str, available_labs: list[dict]) -> dict | None:`
3. **Ошибки:**
   * Функции в `database.py` и `roulette.py` возвращают предсказуемые значения: кортеж `(bool, str)`, `None` или `[]`.
   * В `app.py` перехватывай ошибки и показывай понятные сообщения через `st.error(...)` / `st.warning(...)`, а не трейсбек.

---

## 5. Фокус по модулям

* **`app.py`:** чистый интерфейс, сплит-экран `st.columns([3, 2])`, проверка обязательных полей формы.
* **`database.py`:** параметризованные SQL-запросы с `?` (защита от SQL-инъекций), обязательный `conn.commit()` и `conn.close()`.
* **`roulette.py`:** чистые функции без побочных эффектов: исключение проверки своей работы, валидация отзыва (`len(comment.strip()) >= 50`).

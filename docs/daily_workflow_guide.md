# Как мы работаем с Git

Короткая шпаргалка на каждый день: как брать задачу, писать код в отдельной ветке и отправлять его в общий репозиторий через PR.

---

## Зачем нам ветки и PR?

Ветка `dev` — это наш общий рабочий проект. Чтобы не затереть случайно код друг друга и не ломать проект, когда несколько человек работают одновременно, договоримся о простом процессе:

1. **Ветка (Branch)** — твоя личная песочница / черновик. Здесь можно спокойно экспериментировать и писать код — общий проект в `dev` не пострадает.
2. **Коммит (Commit)** — локальное сохранение точки работы (чекпоинт): зафиксировал, что изменил.
3. **Пуш (Push)** — отправка твоей ветки с компьютера на GitHub.
4. **Pull Request (PR)** — запрос на слияние: «я закончил задачу, гляньте код и залейте в `dev`».

---

## Пошаговый воркфлоу

### 1. Перед началом: получаем свежие изменения

Перед тем как начать писать код, всегда забираем то, что уже успели сделать остальные.

1. В PyCharm посмотри в правый нижний угол: там должна быть выбрана ветка **`dev`**.  
   *(Если нет — кликни по ветке и выбери `dev ➔ Checkout`)*.
2. Нажми **Update Project** (синяя стрелка вниз ⬇️ в правом верхнем углу или `Ctrl + T`).
3. В появившемся окне жми **OK**. Теперь у тебя актуальная версия кода.

---

### 2. Создаем новую ветку под задачу

> В ветку `dev` напрямую ничего не коммитим. Для каждой задачи делаем отдельную ветку.

1. Кликни на название ветки в правом нижнем углу (там сейчас `dev`).
2. Нажми **New Branch...**
3. Введи название латиницей:
   * Название отражает суть изменений, для которых создана ветка. Для первых задач название ветки указано в описании к задаче. Например, `db-models` или `upload-ui`.
4. Галочка **Checkout branch** должна стоять (чтобы сразу переключиться).
5. Жми **Create**. В правом нижнем углу появится имя твоей новой ветки — можно работать.

---

### 3. Пишем код и проверяем локально

Пишем код задачи и проверяем, что всё запускается без ошибок:

* В терминале PyCharm запускаем приложение:
  ```bash
  streamlit run app.py
  ```
* Открываем страницу в браузере, проверяем свой функционал и смотрим, чтобы в консоли не сыпались ошибки.

---

### 4. Фиксируем изменения (Commit)

1. Открываем вкладку **Commit** слева (или жмем `Ctrl + K`).
2. В списке **Changes** отмечаем галочками измененные файлы.

**Что отмечаем галочками:**
* Только свои файлы с кодом или документацией (`.py`, `.md`).

**Что НЕ коммитим (снимаем галочки):**
* `.venv/` (окружение)
* `.idea/` (файлы PyCharm)
* `database.db` и файлы баз данных
* `__pycache__/`

3. **Проверка себя:** кликни дважды по файлу в списке — справа увидишь свои изменения. Убедись, что там нет ничего случайного.
4. Пишем нормальный текст коммита (что сделано):
   * Например: `добавил форму загрузки PDF`, `исправил подсчет баллов`, `добавил информацию о структуре базы данных`.
5. Жмем на стрелку рядом с кнопкой **Commit** и выбираем **Commit and Push...** (или `Ctrl + Alt + K`).

---

### 5. Отправляем ветку на GitHub (Push)

1. Откроется окно **Push Commits**.
2. Проверяем ветку и жмем синюю кнопку **Push**.
3. Снизу всплывет уведомление, что ветка запушена на GitHub.

---

### 6. Открываем Pull Request (PR)

1. Переходим в репозиторий в браузере [github.com/Pavelgrr7/peer-check](https://github.com/Pavelgrr7/peer-check)
2. Сверху появится желтая плашка:
   > **[твоя-ветка] had recent pushes less than a minute ago**  
   > и зеленая кнопка **Compare & pull request**.
3. Жмем **Compare & pull request**.

*(Если плашка не вылезла: вкладка **Pull requests** ➔ кнопка **New pull request** ➔ в поле `compare` выбираем свою ветку).*

4. **Важно проверить направление веток:**
   * Должно быть: `base: dev`, `compare: твоя-ветка`.
   * Если GitHub подставил `base: main`, переключи на **`dev`**!
5. Заполняем короткое описание по шаблону (что за задача, что сделано, чек-лист).
6. Жмем зеленую кнопку **Create pull request**.

Готово, PR открыт и виден в проекте.

---

### 7. Если на ревью попросили внести правки

Обычная рабочая ситуация: наставник посмотрел код и оставил комментарий, что нужно поправить.

> **Не нужно** закрывать PR или создавать новую ветку!

Делается всё в 3 действия:
1. В PyCharm в этой же ветке вносишь исправления.
2. Делаешь Commit и Push.
3. GitHub **сам** добавит новые коммиты в уже открытый PR.

---

### 8. Задача принята (Merged)

Когда PR проверен и слит:
1. В PyCharm переключаешься обратно на ветку `dev` (клик по ветке в правом нижнем углу ➔ `dev ➔ Checkout`).
2. Жмешь **Update Project** (`Ctrl + T`) — у тебя появляется свежий код со всеми принятыми изменениями.
3. Старую ветку задачи можно удалить в списке веток, чтобы не висела.

---

## Если что-то пошло не так

* **Начал писать код прямо в `dev` и забыл создать ветку:**  
  Нормальная ситуация, код стирать не нужно. Жми в правом нижнем углу на `dev` ➔ **New Branch...** ➔ введи название ветки и нажми **Create**. PyCharm сам перенесет все твои незакоммиченные изменения в новую ветку.
* **Сделал Commit, но забыл сделать Push:**  
  Коммит просто сохранился локально. Нажми `Ctrl + Shift + K` (или сверху `Git ➔ Push...`) и отправь его на GitHub.
* **В окне коммита куча странных файлов:**  
  Сними со всех галочки и оставь только те файлы, которые реально редактировал сам.
* **Ошибка или конфликт при пуше:**  
  Ничего не удаляй. Скинь скриншот в наш чат в тг, созвонимся или разберем текстом за пару минут.
